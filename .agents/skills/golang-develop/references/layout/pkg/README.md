# `pkg/`

`pkg/` 放跨应用复用的通用包。

这里的包通常分为两种：

- 一种是业务相关的，但是可能需要被外部使用的，比如 API 或通过 proto 生成的 http 客户端的 SDK。
- 一种是业务无关的，是相对通用的逻辑，通常是一些工具函数，基础能力封装等，他们可能会在后续合并到公共的 kit 库中。

## 什么可以放进 `pkg`

可以放：

- 和具体应用无关的工具函数。
- 多个应用都会用到的基础能力封装。
- 行为清楚、名字能表达用途的小包。

不要放：

- 只被一个应用用到的 service、repository、handler。
- 为了“看起来分层”而提前抽出的接口。
- 只隐藏几行局部逻辑的一次性 helper。

## 判断规则

- 只在一个地方用：先留在调用处。
- 同一个应用内两个地方用：可以考虑放在 `internal/...` 或 `internal/<app>/...`。
- 多个应用都用，且不依赖应用领域概念：再放进 `pkg`。

## 工具函数风格

- 函数名描述行为，不描述调用场景。
- 保持小而直接。
- 测试覆盖边界行为。

例如 `stringx.TrimSplit` 的职责就是：按分隔符 split、trim 每一项、丢弃空项。它不关心调用者是 Redis address、MQ address 还是别的配置。
